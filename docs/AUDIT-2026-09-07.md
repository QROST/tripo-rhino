## 已修复

| 编号 | 优先级 | 原问题及影响 | 本次改进与验证 |
| --- | --- | --- | --- |
| R1 | P1 | IPv6 地址过滤只列举部分禁用段，`::127.0.0.1`、NAT64 和其他特殊用途地址仍能通过；在具备对应路由/转换配置的网络中，可能绕过下载的公网限制。 | 仅放行原生 `2000::/3`，进一步排除协议、文档、6to4 和 scoped 地址；IPv4-mapped 继续检查内嵌 IPv4。新增 17 个边界用例，保留正常公网 IPv4/IPv6 正例。 |
| R2 | P2 | 查询重试把服务端 `Retry-After` 截短为本地最大退避（默认 8 秒），可能在限流冷却结束前再次请求。 | 服务端冷却不再被本地退避上限截短；超过剩余查询预算时直接返回原异常，避免过早请求或超长等待。回归验证超本地上限的实际定时器参数，以及极长冷却下只有一次查询。 |
| R3 | P2 | GHA 基类移除标志没有重新加入时的恢复路径；恢复同一组件后所有菜单操作被永久拒绝。排队的画布回调也未核对组件所属的这次加入。 | 用可测试的组件加入代次管理单一在途操作；重新加入后可以显式操作，旧的付费前置动作、网格发布及两层排队回调失效，已发送请求仍能完成其日志记录。4 个离线生命周期用例通过，GHA 编译通过；真实 Undo/画布操作仍须宿主复验。 |
| R4 | P1 | 标签名直接插入 PowerShell 脚本源码，版本检查发生在脚本解释之后，无法保护特殊字符导致的脚本注入。 | 标签经环境变量作为数据传入，并关闭 checkout 的凭据持久化；遵循 GitHub 的脚本输入处理建议。 |
| R5 | P2 | 打包先删除同版本旧目录、ZIP 和校验文件，随后失败会丢失原候选；ZIP 还遗漏项目许可证和 NOTICE。 | 拒绝已有输出、按版本独占锁、唯一临时目录完整打包后以无覆盖移动发布，ZIP 最后出现；处理失败仅清理本次产物，加入 LICENSE/NOTICE。合成回归覆盖成功布局/哈希、已有输出、锁、压缩失败、发布时冲突及重试。 |

标签传参依据 [GitHub 安全使用参考](https://docs.github.com/en/actions/reference/security/secure-use#good-practices-for-mitigating-script-injection-attacks)。

## 保持的约束及后续验收

- 面板仍把面数限制在 500–200,000；MCP/GHA 仍严格拒绝越界输入。
- 任务创建不自动重试；未知付费结果保留 UUID 和日志；移除 GHA 组件不声称
  已取消远端任务，也不会为重算新建付费请求。
- OBJ/GLB 的大小、路径、哈希、不可变快照、解析预算，以及 native import 的
  Undo/日志约束保留。此次没有为了简化大型 UI/导入文件而改写已验证路径。
- 新二进制尚未安装到 Rhino。本次不能证明 macOS/Windows 宿主加载、GHA
  Undo 恢复、PBR 外观、单位/朝向、单步 Undo、保存重开回放或大模型交互性能。
  具体步骤已补入 [TESTING.md](TESTING.md)，仍需按目标平台执行。
- 源码提交/推送不等同 Yak 发布、签名、公证或部署；打包失败或进程崩溃后的
  冲突处理步骤见 [packaging/README.md](../packaging/README.md)。
